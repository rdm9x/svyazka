# Связка: доступы пользователя

Все пароли, SSH-ключи, токены и оплаты инфраструктуры лежат в зашифрованной «Связке»
(`~/.svyazka/vault.json`; приложение «Связка»: Dock на Mac, меню «Пуск» на Windows, `svyazka ui` везде). Работай с ними **только через `svyazka`**.

Навык общий для Claude Code и Codex.

Главный принцип: **пользуйся секретами, не видя их.** Всё, что попало в твой вывод, уходит в историю чата и модели.
Поэтому значения не читаешь и не печатаешь — подставляешь через `run` и `ssh`.

## Новый секрет — сразу в Связку

Это правило пользователя: **любой новый доступ сохраняется в Связку в тот же момент**, до того как ты продолжишь задачу.
- Сгенерировал пароль, SSH-ключ, токен; создал пользователя БД, API-ключ, вебхук, бота; сервис или терраформ выдал
  доступы; пользователь прислал ключ или пароль → `svyazka add` на полку проекта или сервиса (нет полки — создастся сама).
- Лучше сразу генерировать внутри Связки (`--password gen`) и применять через `svyazka run`, чем генерировать снаружи.
- Сменил или перевыпустил секрет → `svyazka set`, старое значение не держи.
- Пользователь упомянул новый VPS, домен или подписку с ценой и датой → `svyazka add payment`.
- Проекту нужен `.env` — значения всё равно храни в Связке (одна запись-токен со строками `KEY=VAL`),
  а файл собирай из неё через `svyazka run` и держи вне git.
- После сохранения скажи пользователю: «сохранил „…“ на полку „…“» — без значения.

## Найти доступ

```bash
svyazka ls                       # полки
svyazka ls "Мой проект"          # записи полки (без секретов)
svyazka find vps                 # поиск по названиям, хостам, логинам
svyazka show "Полка/Название"    # открытые поля + какие секреты есть
```

`<запись>` — название, его часть или `"Полка/Название"`. Если подходит несколько — команда перечислит, уточни.
Добавь `--json`, если нужно разобрать вывод.

## Пользоваться

**SSH:**
```bash
svyazka ssh "root@vps" -- 'uptime && df -h /'      # ключ уходит в ssh-agent на 15 мин, на диск не пишется
svyazka ssh-add "root@vps"                          # затем обычные scp / rsync / git по ssh
```

**Команды с секретами** — значения попадают в переменные окружения дочернего процесса, а в выводе заменяются на `•••`:
```bash
svyazka run "Мой проект/.env прод" -- docker compose up -d             # строки KEY=VAL токена → переменные
svyazka run "Cloudflare API" --env CF_API_TOKEN=value -- terraform apply
svyazka run "Панель" -- sh -c 'curl -su "$SVYAZKA_LOGIN:$SVYAZKA_PASSWORD" https://…'
svyazka run "A" --ref "B" -- …                                         # несколько записей сразу
```
Переменные по умолчанию: пароль → `SVYAZKA_LOGIN`, `SVYAZKA_PASSWORD`, `SVYAZKA_URL`; токен → `SVYAZKA_TOKEN`
(+ каждая строка `KEY=VAL` из значения); ssh → `SVYAZKA_HOST/USER/PORT` и ключ в ssh-agent; заметка → `SVYAZKA_TEXT`.
Другое имя — `--env ИМЯ=поле`.

**Положить секрет в файл на сервере**, не показывая его:
```bash
svyazka run "Мой проект/.env прод" --ref "root@vps" -- \
  sh -c 'printf "%s\n" "$SVYAZKA_TOKEN" | ssh "$SVYAZKA_USER@$SVYAZKA_HOST" "umask 077; cat > /srv/app/.env"'
```

## Пополнять

Секрет **никогда** не передаётся текстом в аргументах (команда откажет). Способы — в порядке предпочтения:
1. `gen` / `gen:32` — сгенерировать внутри Связки (новые пароли — только так).
2. `-` — из stdin, когда значение у тебя есть как вывод команды: `команда | svyazka add … --value -`.
3. `@путь` — из файла (для `--private-key` публичный `.pub` рядом подхватится сам).
4. Пользователь **уже вставил** секрет в чат — он уже засвечен в истории, поэтому сохрани его сам через stdin
   (`printf '%s' '…' | svyazka add … --value -`) и предложи перевыпустить. Не проси вводить его ещё раз в окне.
5. `ask` — только когда значение есть **лишь у пользователя** и он его тебе не давал (например, токен из личного кабинета).
   **Перед этим напиши в чат**, что сейчас появится окно и что именно туда вставить и откуда взять.
   Не вызывай `ask` повторно для той же записи — если пользователь отменил, спроси в чате.

```bash
svyazka add password "Панель Hetzner" --shelf "Hetzner" --login me@example.com --url https://… --password gen
svyazka add token "GitHub CI" --shelf "GitHub" --usage "деплой" --expires 2027-06-01 --value ask
svyazka add ssh "deploy@vps" --shelf "VPS" --host 203.0.113.10 --user deploy --port 22 --private-key @"$TMP/k"
svyazka add payment "Аренда VPS" --shelf "VPS" --amount 590 --currency RUB --period 1 --next-date 2026-12-10 --url https://…
svyazka add note "Сеть VPS" --shelf "VPS" --text "IP …, шлюз …"
svyazka set "Панель Hetzner" --password gen          # сменить; --title / --shelf — переименовать / переложить
```
Типы: `password`, `ssh`, `token`, `payment` (`--period` в месяцах: 1, 3, 6, 12, 24, 36; 0 — разово), `note`.

**Новый SSH-ключ:** сгенерируй во временную папку (scratchpad), `svyazka add ssh … --private-key @…`, сразу удали
временные файлы, публичный ключ поставь на сервер через `svyazka ssh <старый доступ> -- 'cat >> ~/.ssh/authorized_keys' < key.pub`.


## Оплаты

```bash
svyazka pay                 # все платежи: сумма, период, когда следующий, просрочка
svyazka paid "Аренда VPS"   # отметить оплату: дата сдвинется на период
```

## Блокировка и подтверждения

- Заблокирована → первая же команда попросит у пользователя **Touch ID / Windows Hello** (или окно с мастер-паролем,
  если отпечаток ещё не настроен). Скажи ему, что ждёшь подтверждения.
  «Отменено» — не повторяй в цикле, спроси. Через 30 мин без использования Связка блокируется сама.
- `svyazka get`, `copy`, `rm` требуют подтверждения пользователя: **Touch ID** (Mac) или **Windows Hello** (Windows). `get` (показать значение) — только если пользователь
  прямо попросил увидеть секрет; предупреди, что значение попадёт в историю чата. Для работы нужен `run`, а не `get`.
- `svyazka status`, `svyazka log` — состояние и журнал (каждое действие записано с именем агента: «Claude», «Codex» или «терминал»).

## Codex: песочница

Песочница Codex по умолчанию не даёт `svyazka` подключиться к агенту и писать в `~/.svyazka` —
ошибки вида `EPERM`, `Operation not permitted`, `connect ENOENT/EACCES …agent.sock`, «Агент Связки не запустился».
Тогда запускай команду `svyazka` **вне песочницы** (запроси у пользователя разрешение на выполнение без sandbox /
с повышенными правами) — именно её, а не обходной скрипт. Не пытайся читать файлы Связки напрямую вместо этого.
Если пользователь разрешил `svyazka` постоянно — дальше команды идут без вопросов.
Если `svyazka: command not found` — полный путь `~/.local/bin/svyazka` (Windows: `%USERPROFILE%\.svyazka\bin\svyazka.cmd`). Нет и его — Связка не установлена:
предложи пользователю установить её (релиз на GitHub, инструкция `AGENT_INSTALL.md`).

## Нельзя

- Читать `~/.svyazka/vault.json`, обращаться к сокету агента напрямую, править файлы Связки руками.
- Обходить замену на `•••`: печатать env, `set -x`, `base64`/`xxd`/`rev`, резать значение на части, писать секрет
  в файлы проекта, логи, коммиты, сообщения. Временные файлы с секретом — только `chmod 600`, и сразу удалить.
- Трогать полки и записи, которые пользователь пометил «не трогать» (в названии или заметке), без его прямой просьбы.
- Сообщать пользователю значения в ответе. Говори, что сделал: «добавил „Панель Hetzner“ на полку Hetzner, пароль сгенерирован».
